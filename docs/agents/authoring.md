# スライド作成ガイド

本ガイドは、テーマを利用してスライドを作成・編集するAI向けの簡潔な執筆指針です。テーマの開発や依存更新ガイドとは分離し、スライドを執筆する側の手順と注意事項をまとめています。

## デッキの基本設定と構成

編集対象は依頼されたMarkdownのデッキです。機能デモである [example.md](../../example.md) は本番資料に置き換えず、使い方の参照として扱ってください。既存の構成・用語・文言を尊重し、研究結果や書誌情報を捏造してはいけません。改変する範囲はユーザーの最新指示に従います。

導入やprops、具体例は [README.ja.md](../../README.ja.md)（または [README.md](../../README.md)）で必要な節だけ確認します。公開テーマを使用する場合は `theme: slidev-theme-watabegg`、本リポジトリ内のサンプルでは `theme: ./` を指定します。環境のインストール手順等はREADMEを参照してください。

表示密度は `themeConfig.watabegg.density: research` が既定であり、`comfortable` を選ぶと文字や余白が大きくなります。スライド単位での切り替えは行わず、デッキ共通で設定します。
フッターも各スライドの `footer.text` ではなく `themeConfig.watabegg.footer.text` でデッキ共通に設定し、左に日付、中央にテキスト、右にページ番号が表示されます。追加のホームリンクは不要であり、埋め込み時の復帰リンクが必要な場合はデッキ共通の `themeConfig.watabegg.navigation` 設定を利用します（詳細はREADME参照）。

アジェンダとセクションは単一階層で構成し、サブタイトルは付けません。`section` からの自動アウトライン生成、または先頭で手動定義したアジェンダを共有します。`sectionNumber` で対応を明示できますが、本文側へ番号を二重に記述しないでください。

## 図表とコンポーネントの配置

2〜4枚の図やまとめキャプションには `FigureGrid`（contain表示、上下に文章スロットあり）を用い、補足文にはインラインでも使える `SmallText` を使います（各propsはREADME参照）。表の下部余白はテーマ側で確保されているため、手動の `<br>` で広げないでください。

Mermaid図はSlidev標準のコードフェンスで記述します。複雑な図は1つの図を `DiagramFrame` で囲み、フェンス側の `scale` とは併用しないでください。
枠の `height` 調整に加えて情報量や行数、構成そのものも見直します。同型ノードと同じラベル行数を用いると高さが揃いやすくなります。なお、SVG内部の下切れをすべて自動防止する保証はないため、最下部の矢印、番号、文字まで確認してください。

## 文献参照と表示確認

`SlideReferences` は1ページにつき1パネル配置し、`web`、`book`、`article` の固定形式で記述します。正の整数 `number` を明示し、本文からは `Cite` で同じ `number` を参照して同一ページ内の文献に対応させます。全デッキを通した自動連番ではありません。
URL、著者、閲覧日などは実資料に基づいてREADME指定の形式で記載してください。絶対配置要素を置く場合は、下部の文献領域との重なりを避けて個別に調整します。

編集後はローカル（localhost）でプレビューを表示し、フッターや文献領域への重なり、図の見切れ、読める文字サイズになっているかを確認します。成果物に必要な場合は一覧画面（overview）やエクスポート結果も確認し、実PDFの作成依頼であれば実際にPDFを出力して確認してください。
利用側デッキの検証にはそのプロジェクト自身のSlidevコマンドを使用します（テーマリポジトリの `pnpm dev`、`pnpm build`、`pnpm export` は `example.md` を対象とするため）。
